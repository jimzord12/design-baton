# Issue draft

Use a short title naming the observed behavior or enhancement. Replace the
guidance below with real, public-safe evidence; do not submit this template as-is.

## Version and context

- Pinned Design Baton bundle, tag, and full commit:
- Affected component IDs and versions from that pinned manifest:
- Relevant runtime/tool environment, only where it changes reproduction:
- Slice activity that exposed the feedback, described without private details:

## Observed behavior

Describe what happened and supporting evidence. For enhancements, describe the
current limitation; distinguish observation, interpretation, and prediction.

## Expected behavior or desired benefit

State the procedure guarantee or proposed improvement. Do not present a new
expectation as an already promised behavior.

## Reproduction or concrete example

Provide minimal steps, a sanitized input/output example, or an honest account
when reproducibility is not established. Include only public-safe references.

## Impact

Explain the consequence for usability, correctness, continuity, or maintenance.
Report frequency or measurements only when actually observed.

## Suggested improvement and uncertainty

Describe a candidate remedy or leave the remedy open. Note alternatives and
unresolved questions when they materially affect the proposed change.

## Acceptance criteria

List observable outcomes that would demonstrate an improvement. Include any
relevant compatibility, approval, or preservation requirements.

## Related issues

Link checked related issues, or explicitly state that issue lookup was unavailable.
